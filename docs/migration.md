# Миграция с 1.x и 2.x на 3.0

Legacy-код сохранён без изменений в `legacy/1.x` на коммите `b587158`;
прежние теги остаются на месте. Python 2 не поддерживается новой веткой.
Для старых приложений закрепите `petrovich==1.0.0` и поддерживайте исправления
отдельно в legacy-ветке.

В PyPI также сохранён релиз `2.0.1` для Python 3.6+. Его исходников нет
в текущей истории GitHub: ветка `legacy/1.x` сохраняет именно исходный checkout
1.x, а не код опубликованного 2.0.1. Новая реализация имеет номер `3.0.0`,
поскольку повышает минимальную версию Python и меняет поведение API.

Основные импорты `from petrovich.main import Petrovich` и
`from petrovich.enums import Case, Gender` сохранены. Сохранены методы,
аргумент `rules_path`, числовые значения пяти падежей (0–4), `Case.CASES`
и псевдоним `Gender.ANDRGN`. Доступны короткие импорты из `petrovich`.

Изменения поведения:

- Требуется Python 3.12+. Входные имена — `str`, не `bytes`.
- `Case` — `IntEnum`, `Gender` — `StrEnum`; добавлен `Case.NOMINATIVE = 5`.
- Некорректные падежи и род вызывают `ValueError`.
- Модификатор `.` оставляет слово неизменным и завершает поиск.
- Общие правила используются и при явно заданном роде.
- Исключения работают внутри составных имён; тег `first_word` действует только
  на первый компонент составного имени.
- Суффиксы ищутся без учёта регистра; верхний регистр сохраняется.
- Ошибки формата правил — `RulesError`, ошибки файловой системы — `OSError`.
- Изменяемое внутреннее поле `data` больше не предоставляется. Для собственных
  правил используйте JSON или `Petrovich(rules=load_rules(path))`.
- Изменился снимок upstream-правил. Для воспроизводимости на прежних данных
  передайте собственный файл явно.

Для восстановления legacy checkout с submodule используйте HTTPS:

```sh
git switch legacy/1.x
git -c url.https://github.com/.insteadOf=git://github.com/ submodule update --init
```

Перед переводом приложения проверьте его набор имён и явно задайте род там,
где он известен. Без рода результат остаётся эвристическим.
